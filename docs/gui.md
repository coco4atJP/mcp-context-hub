# 小窓で管理する

```sh
mcp-context-hub gui
```

ブラウザが開き、CLIと同じ設定を管理できます。右上の「小窓で開く」を押すと、540 × 760pxを目安に別ウィンドウを開きます。ウィンドウの形や実際のサイズはブラウザに依存します。通常のタブのままでも使えます。Windows・macOSで同じ画面を利用でき、Electronなどのデスクトップランタイムは必要ありません。

アプリ内ブラウザなどで小窓を開けない場合は案内を表示します。通常のブラウザでポップアップを許可するか、そのままタブで操作してください。

初回は `mcp-context-hub init` で空の設定を作ります。既存設定があればそのまま使います。

## よく使う操作

| 画面 | 操作 |
| --- | --- |
| サーバー | 検索、ON/OFF、すべてOFF、HTTP・ローカルコマンド・テンプレートから追加 |
| サーバーの詳細 | Skillの一覧、ローカル原本へのSkill添付、共有先への公開、登録の削除 |
| 同期 | URL／QRペアリング・LAN同期・自動起動、フォルダー選択・接続・解除、同期確認、受信した接続情報とSkillの閲覧、版の承認・競合の解決 |
| 安全性 | 標準／フルアクセスの選択、14項目のスイッチ、初期値への復帰、詳細設定のJSON編集 |

追加したサーバーは初期状態ではOFFになっています。ONに切り替えても、Agentがツールを要求するまでは起動しません。ON/OFFはこの端末の同じconfigを使うHub間で共有され、他端末には同期しません。Agentによる起動を禁止した `allowAgentEnable: false` の登録は、GUI上でもロック状態として表示されます。変更する場合は詳細設定を編集してください。

ローカルコマンドの引数は1行に1つ入力します。シェル形式の引用符や `&&` による連結は使いません。Windowsの絶対パスや認証ヘッダー、環境変数、ツール別のSkill紐づけは詳細設定で編集できます。詳細設定を開いたときだけ、認証設定を含むconfigの内容を表示します。

Skill添付では `SKILL.md` が入ったフォルダーとSkill IDを指定します。内容を検証してからローカル原本へ登録します。LANの自動共有がONなら原本の編集内容も自動で反映されます。フォルダー方式や自動共有がOFFの場合は、再び「共有する」を押して新しい版を公開します。共有から受信した登録にローカル原本がない場合は、共有元でSkillを編集してください。

同期のフォルダー選択はmacOS・Windowsの標準ダイアログを利用します。ダイアログを使えない環境では絶対パスを直接入力できます。Linuxは `zenity` があればフォルダー選択を利用できます。GUIをLANに公開する必要はなく、各端末でGUIを起動して同じ共有フォルダーを指定します。

受信版は「内容を見る」で接続先・許可ツール・Skillの各ファイルを確認できます。本文はテキストとして表示し、HTMLやスクリプトを実行しません。承認は画面で確認したSHA-256の版だけに適用します。確認中に新しい版を受信した場合は承認が拒否されるため、一度閉じて最新の内容を開き直してください。

## URL・QRで接続

「同期 → 端末を追加」で招待を発行し、もう一方の端末で開くか「招待を受け取る」に貼り付けます。両画面の6桁の番号が一致していることを確認すると自動で同期が始まります。カメラやQR画像も利用できます。「同期と自動起動の設定」からログイン時の起動・URL登録、自動共有を管理できます。[LANペアリングの詳しい手順](lan.md)

## CLIとの併用と終了

```sh
# 別の設定を使う
mcp-context-hub gui --config /absolute/path/config.json

# ブラウザを開かず、フォアグラウンドで待機する
mcp-context-hub gui --no-open

# 待ち受けポートを指定する（省略時は設定パスから選択）
mcp-context-hub gui --port 8787
```

通常の `gui` はブラウザを開いてCLIを終了し、管理用プロセスだけを残します。同じ設定で再度開くと起動中の画面を再利用します。LAN同期をONにした場合や `lan start` では、画面を閉じても常駐して同期を続けます。プロセスの終了は `lan stop` を使います。LANを使わない通常のGUIは、GUIの「終了」、フォアグラウンド実行時の Ctrl+C、または管理画面から5分間通信がない場合に停止します。ブラウザによっては非アクティブなバックグラウンドタブの通信が休止するため、その場合も停止します。再度 `mcp-context-hub gui` で開けます。GUIを終了しても、MCPクライアントが起動したHubやCLIは引き続き利用できます。

v0.4以降の稼働中Hubは、GUI・CLI・エディターで行ったconfigの変更内容を次回のMCPリクエスト時に自動で再読み込みします。その際は古い接続を閉じ、処理中の要求を取り消し、結果キャッシュ・focus条件・出力量の一時設定をリセットします。保存済みのON/OFF状態は維持されます。別プロセスで実行中の要求を即座に取り消す保証はなく、既に行われた外部操作を取り消すこともできません。

v0.5へのアップデート直後は、MCPクライアントからHubを一度再起動して新しい設定形式を読み込めるようにしてください。登録ツールは5個のままです。

## グローバルSkills・設定

「同期」の「グローバルSkills・設定」を開き、全Skills／選択したSkillsと設定ファイルを指定して保存します。「登録済みの対象を確認」で共有範囲とエラーを確認できます。受信版はファイルごとに内容を見て承認できます。フルアクセスでは競合のない受信版を自動適用します。[範囲・バックアップ・CLI](global-agents.md)

## 安全性と保存

- GUIは `127.0.0.1` だけで待ち受け、外部からの接続を許可するオプションを持ちません。
- 起動ごとにランダムな認証トークンを生成し、全管理APIで検証します。起動URLのフラグメントから画面内に取り込み、アドレスバーから取り除きます。URLは他人と共有しないでください。
- Host・Origin・Fetch Metadataを検証し、外部サイトからの要求を拒否します。CORSは許可せず、CSPで外部スクリプト・埋め込み・フォーム送信を制限します。
- 設定の更新は排他ロックと版の照合を使います。別画面やCLIで変更済みの場合は古い内容による上書きを拒否します。入力形式を検証し、不正な設定は保存しません。
- 日常の一覧には起動コマンドや認証情報を含めません。詳細設定には所有者が編集するための内容を表示します。
- 保護を緩める一部のスイッチ、共有公開、削除は確認画面を出します。GUI自身の認証やループバック制限はスイッチで無効になりません。

管理APIはMCPには公開しません。同じOSユーザー権限でconfigやプロセスへアクセスできるプログラムから所有者設定を隔離する仕組みではありません。共有フォルダーや実行するMCPに関する制約は、[安全性設定](security.md)と[同期](sync.md)を参照してください。
